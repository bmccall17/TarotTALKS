# v1.7.1 - ISR Cache Invalidation Fix

**Released:** Mar 11, 2026

## Summary
Fixed a bug where admin panel edits (talk descriptions, card details, theme updates) were not reflected on public-facing pages due to broken ISR cache invalidation. The `revalidateTag()` calls had an invalid second argument and were missing `revalidatePath()` calls needed to bust the full-route ISR cache.

---

## Bug Fixed

- **Stale public pages after admin edits:** When updating a talk description (or any entity) in the admin panel, the public detail page continued showing old content for up to 1 hour (ISR cache TTL). Root cause was two-fold:
  1. `revalidateTag('talks', 'max')` — `revalidateTag()` only accepts a single string argument; the `'max'` was silently ignored
  2. `revalidateTag()` alone doesn't bust Next.js ISR full-route cache — `revalidatePath()` is required to invalidate the cached HTML

## Changes

- Fixed all `revalidateTag('...', 'max')` calls to `revalidateTag('...')` across 8 admin API routes
- Added `revalidatePath()` calls to invalidate specific detail pages (`/talks/[slug]`, `/cards/[slug]`, `/themes/[slug]`) and listing pages (`/talks`, `/cards`, `/themes`) after every admin create/update/delete operation
