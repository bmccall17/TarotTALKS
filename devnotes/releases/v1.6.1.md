# v1.6.1 - Social Presence Sprinkle & Mention Dedup Fix

**Released:** Feb 6, 2026

## Summary
Expands social presence across the entire public-facing site with static profile links and a new data-driven Social Trail on detail pages, plus adds admin controls for public share visibility and fixes a duplicate-mention bug in the Bluesky scanner.

---

## Features

### Part 1: Static SocialLinks on All Pages
- **SocialLinks component** added to the bottom of every public page: Cards list, Talks list, Card detail, Talk detail, Theme detail, and Spread pages
- Subtle `opacity-60 hover:opacity-100` treatment — quiet social proof, not distracting

### Part 2: Signal Deck Social Trail
- **New `SocialTrail` component**: Data-driven row of platform icons (Bluesky, X, Threads, LinkedIn, Instagram) on Card and Talk detail pages showing actual social posts for that specific card/talk
- Each icon links to the real social post with a relative timestamp underneath ("3d", "1w", "2mo")
- Renders nothing when no public shares exist — no empty state, no "Shared on" label
- **New `show_publicly` column** on `social_shares`: Admin-controlled boolean for which shares appear publicly
- **New public query** (`getPublicSharesForCard`, `getPublicSharesForTalk`): Returns only `platform`, `postUrl`, `postedAt` — no notes, metrics, handles, or drafts leak

### Part 3: Admin UI for Public Visibility
- **ShareRow**: Eye/eye-off toggle icon next to status badge for per-share public visibility control
- **NewShareForm**: "Show on public site" checkbox, auto-checked when status is `posted` or `verified`
- **SharesList**: Type updated to include `showPublicly`

### Bug Fix: Bluesky Scan Duplicate Mentions
- **Root cause**: `mentionExistsByAtUri()` only checked `atUri`, but manually-logged shares store `postUrl` without `atUri`, so the scanner didn't recognize them as duplicates
- **Fix**: Dedup check now uses `atUri OR postUrl`, catching manually-logged shares

---

## Database Migration

Run in Supabase SQL Editor **before deploying**:

```sql
ALTER TABLE social_shares ADD COLUMN show_publicly BOOLEAN NOT NULL DEFAULT false;

UPDATE social_shares SET show_publicly = true
WHERE status IN ('posted', 'verified') AND post_url IS NOT NULL;

CREATE INDEX idx_social_shares_public ON social_shares (show_publicly, card_id, talk_id)
WHERE show_publicly = true;
```
