# v1.6.7 - Admin Portal Performance Rescue ⚡🏥

**Released:** Mar 4, 2026

## Summary
Fixed critical admin portal performance issues where 11 of 12 API routes were timing out (10s+), leaving most admin pages non-functional. Root causes: Drizzle ORM Date serialization bugs, Vercel function timeout limits, and a missing database index. Final result: 25/26 endpoints passing, average response time 149ms.

---

## Features
- **DB Health Check endpoint** (`/api/admin/health`) — Tests DB connectivity, query timing, index existence, and EXPLAIN ANALYZE output for diagnostics
- **Behavior debug endpoint** (`/api/admin/health/behavior-debug`) — Runs behavior queries individually with per-query timing
- **Admin diagnostics script** (`/admin-diagnostics.js`) — Browser console tool testing all 26 admin endpoints with timing, pass/fail, scorecard, and slow endpoint visualization
- **Dashboard SSR mega-query** — Consolidated ~23 sequential dashboard queries into a single SQL query with subselects (80% faster)
- **Behavior stats consolidation** — Reduced from 12 sequential queries to 4 parallel queries (68% faster)

---

## Bugs Fixed
- **Drizzle Date serialization** — `db.execute(sql\`...${dateObject}...\`)` silently hangs when JavaScript Date objects are passed as parameters. All instances converted to ISO strings or SQL date functions (`CURRENT_DATE`)
- **Drizzle query builder Date objects** — `gte(column, dateObject)` on `behaviorEvents` also hangs. Replaced with `sql\`column >= ${isoString}\``
- **Vercel 10s function timeout** — Admin API routes exceeded default 10s serverless timeout on cold starts. Added `maxDuration = 30` to all admin API routes
- **Wrong composite index** — Schema had `(event_name, timestamp)` but queries filter by `(event_name, created_at)`. Fixed schema and SQL migration
- **LIKE full-scan filter** — `LIKE '%is_test%'` replaced with `properties::jsonb ->> 'is_test' IS DISTINCT FROM 'true'` (index-friendly)
- **SQL FILTER clause syntax** — `COUNT(*) FILTER (WHERE ...)::int` in subselects caused parse errors. Replaced with `WHERE` clauses
- **Error message SQL leak** — Dashboard error page displayed raw SQL query text. Truncated to first line, max 200 chars
