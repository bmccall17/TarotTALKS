# v1.6.6 - Auto-Refresh Bluesky Engagement Metrics

**Released:** Feb 27, 2026

## Summary
Automates Bluesky engagement metric collection via a weekly Vercel Cron job and an admin "Refresh All" button. Adds visible staleness indicators to every Bluesky share row so you know at a glance whether metrics are current.

---

## Features
- **Vercel Cron Job** — weekly Monday 06:00 UTC batch refresh of up to 18 stale Bluesky shares (stale-first ordering, 8.5s time guard)
- **"Refresh All" admin button** — butterfly-branded manual trigger in Signal Deck header, calls same endpoint with admin cookie auth
- **Staleness indicator** — green dot + relative timestamp for fresh metrics (< 7 days), amber for stale or never-refreshed
- **AT URI backfill** — shares with only a `postUrl` (no `atUri`) get their `atUri` column automatically populated on first refresh
- **Build fix** — `/talks` page switched to `force-dynamic` to prevent static generation timeout during Vercel builds

---

## Files Changed

### New Files
- `app/api/cron/refresh-bluesky-metrics/route.ts` — Cron/admin endpoint: fetches stale Bluesky shares, refreshes metrics via public AT Protocol API, backfills atUri
- `vercel.json` — Vercel Cron configuration (weekly Monday schedule)
- `components/admin/signal-deck/AutoRefreshStatus.tsx` — "Refresh All" button component with result display

### Modified Files
- `lib/db/queries/admin-social-shares.ts` — Added `getStaleBlueskyShares()` query (stale-first, limit 18)
- `components/admin/signal-deck/SharesList.tsx` — Integrated AutoRefreshStatus widget in header
- `components/admin/signal-deck/MetricsDisplay.tsx` — Added staleness dot + relative timestamp next to refresh button
- `app/talks/page.tsx` — Added `export const dynamic = 'force-dynamic'` to prevent build-time static generation timeout

---

## Environment Setup
- **New env var:** `CRON_SECRET` — add in Vercel Dashboard (`openssl rand -hex 32`). Required for Vercel Cron auth; admin button works without it via existing `ADMIN_TOKEN` cookie.
