# v1.3.9 - ReadMySpread Go-Live Migration

**Released:** February 1, 2026

## Summary

Migrated the ReadMySpread feature from staging (`/update`) to production routes. Social sharing links now work correctly on LinkedIn, Twitter, and Facebook. The homepage now uses the new CardCascadeV2 component with integrated spread reading functionality.

---

## What Changed

### Production Routes Created

**Spread Pages (`app/spreads/[id]/`):**
- `page.tsx` - Server component with full OG metadata
- `SpreadPageContent.tsx` - Client component for spread display
- `opengraph-image.tsx` - Dynamic OG image generation (1200x630)
- `twitter-image.tsx` - Dynamic Twitter card image generation

**API Routes (`app/api/spreads/`):**
- `spread-reading/route.ts` - POST endpoint for generating readings
- `[id]/route.ts` - GET endpoint for fetching spread data

### Homepage Updated

- Now uses `CardCascadeV2` instead of `CardCascade`
- ReadMySpreadModal integrated directly into the card cascade experience
- Users can now "Read My Spread" directly from the homepage

### API Endpoint Updated

- `ReadMySpreadModal` now calls `/api/spreads/spread-reading` (was `/api/update/spread-reading`)

### Staging Routes Removed

- Deleted `app/update/` directory (entire staging route structure)
- Deleted `app/api/update/` directory (staging API endpoints)

---

## Why This Matters

**Before:** Social sharing links pointed to `/update/spreads/[id]` which was a staging route. When users shared spreads on LinkedIn, Twitter, or Facebook, the platforms would 404 when trying to fetch OG images.

**After:** Share links now point to `/spreads/[id]` - a proper production route with full OG image support. Social platforms can now properly render preview cards with the spread's tarot cards, recommended talk, and rationale.
