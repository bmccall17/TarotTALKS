[1.2] API KEY EXPOSURE IN LOGS                            [CRITICAL]
  File: lib/services/bluesky.ts:36
  Finding: Bluesky app password prefix logged to console:
    `console.log('[Bluesky Auth] BLUESKY_APP_PASSWORD:', password ? \`${password.substring(0, 4)}...\` : 'NOT SET');`
  The first 4 characters of the app password are written to Vercel logs

[1.3] FETCH TIMEOUT / ABORT                                  [HIGH]
  Files: lib/services/gemini.ts:211, lib/services/youtube.ts:92,
         lib/services/bluesky.ts:108,147,185,250, lib/services/replicate-upscale.ts:87
  Finding: Zero fetch calls across all 4 service files use AbortController
  or the `signal` option. No timeout protection on any external HTTP request.
  Impact: A slow or unresponsive external API (Gemini, YouTube, Bluesky,
  Replicate) will hang the serverless function until Vercel's hard timeout
  (10s hobby / 60s pro) kills it. During that time, the function consumes
  resources and the user gets no response.
  Recommendation: Add AbortController with a 8-second signal to all
  external fetch calls:
    ```
    const controller = new AbortController();
    const timeout = setTimeout(() => controller.abort(), 8000);
    const response = await fetch(url, { signal: controller.signal, ... });
    clearTimeout(timeout);
    ```

[2.5] bestTalkIndex BOUNDS CHECK                             [HIGH]
  File: app/api/spreads/spread-reading/route.ts:233
  Finding: The AI-returned `bestTalkIndex` is used to index into
  `allCandidates` without any bounds checking:
    ```
    const winner = allCandidates[selection.bestTalkIndex];
    ```
  The gemini.ts selectBestTalkWithAI function (line 680) validates that
  `bestTalkIndex` is a number, but does NOT check if it's within the
  range [0, candidates.length - 1]. The AI could return:
    - A negative number → `winner` is `undefined` → crash at `winner.source`
    - An index >= array length → `winner` is `undefined` → crash at `winner.source`
  Impact: An out-of-range AI response crashes the spread-reading endpoint
  with a TypeError, returning a 500 to the user. Since this is the
  primary user-facing feature, this is a reliability risk.
  Recommendation: Add bounds validation in either gemini.ts or the route:
    ```
    if (selection.bestTalkIndex < 0 || selection.bestTalkIndex >= allCandidates.length) {
      // Fall back to first candidate or treat as error
      selection.bestTalkIndex = 0;
    }
    ```

[2.8] PROMPT INJECTION VIA focusText                         [HIGH]
  Files: lib/services/gemini.ts:458, lib/services/gemini.ts:533
  Finding: User-supplied `focusText` is interpolated directly into Gemini
  prompts without any sanitization, length limiting, or guardrails:
    Line 458 (generateSpreadRationale):
      `${focusText ? \`## USER FOCUS\n"${focusText}"\n\` : ''}`
    Line 533 (generateSynthesisAndQueries):
      `${focusText ? \`Context: "${focusText}"\n\` : ''}`
  The spread-reading route passes `focusText` from the POST body directly:
    route.ts:45: `const { ..., focusText, ... } = body;`
    route.ts:137: `focusText: focusText,`
  No validation, no length check, no sanitization anywhere in the chain.
  Impact: A malicious user could inject prompt manipulation text to:
    - Override the system prompt and change AI behavior
    - Extract system prompt contents
    - Generate harmful or off-brand content
    - Cause the AI to return malformed JSON, breaking the flow
  Compound: Combined with [1.5] (no rate limiting on spread-reading),
  an attacker can automate prompt injection at scale.
  Recommendation: At minimum:
    1. Limit focusText length (e.g., 500 characters)
    2. Strip markdown/code block syntax that could escape the prompt context
    3. Validate against obvious injection patterns

[2.9] COST LOGGING FIRE-AND-FORGET                          [MEDIUM]
  File: lib/services/gemini.ts:157,183,273,289,318,339,364,377
  Finding: All 8 logApiCall invocations in gemini.ts are called WITHOUT
  `await`. The function signature is `async function logApiCall(...)` which
  returns a Promise, but the calls look like:
    ```
    logApiCall({...});  // no await
    ```
  In contrast, replicate-upscale.ts correctly uses `await logApiCall(...)`.
  Impact: When the serverless function exits after returning a response,
  the un-awaited database insert may be killed before completing. This
  means cost records for Gemini calls can be silently lost — especially
  for the success path at line 339, which is the most important record.
  On Vercel serverless, the runtime may terminate the function immediately
  after the response is sent, before background promises complete.
  Recommendation: Either `await` all logApiCall calls, or use Vercel's
  `waitUntil()` API to keep the function alive until logging completes.
